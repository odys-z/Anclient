# ISSUE MERGE-WEBROOT: one way to find the album web url

- Status: open, deferred to the version after portfolio-0.8
- Tag in code: `ISSUE MERGE-WEBROOT` (grep it in Anclient and semantic-jserv)
- Since: Anclient `2d81ff2`, semantic-jserv `95b6f72` (branch `portfolio-0.8`)

## Problem

The desktop and Android clients find the album web url in two different ways.

| | Android (example.android) | Desktop (example.slint) |
|---|---|---|
| Request | `AlbumReq.A.getPrefs` on port `docoll`, after login | `EchoReq.A.pubConfig` on port `echo`, no session |
| Server | `SynDocollects.profile()` | `AlbumEcho.pubConfg()` |
| Web root of | the user's org: `org.webroot`, or `getLocalWebroot(https)` if it is this synode | always the pinged synode |
| Reply | `AlbumResp.profils.webnode`, `http(s)://ip[:port]` | `AnsonResp.m`, `ip:port`, no scheme |
| Client | `AlbumApp.login()`, `PrefsWrapper.policy2Prefs()` | `Slingleton::weburl_of()`, `ping_synode()` |

They agree only when `org.webroot` is the pinged synode. If it is another synode, e.g. a hub,
Android opens the hub's album page and the desktop opens the pinged synode's.

## Why not merged in 0.8

The C++ client can't deserialize `AlbumResp.profils`. There are no ASTs or generated types for
`io.oz.album.peer.AlbumResp`, `Profiles` or `AlbumReq`, and the deserializer picks types by the
declared field, not by `"type"`, so a plain `AnsonResp` can't carry it.

## To merge

Desktop (Anclient, example.slint):

1. ASTs and generated types:
   - `io.oz.album.peer.Profiles` (base `Anson`): `uid`, `defltAlbum`, `webnode`, `servroot`, `home`, `servId`, `maxUsers`, `servtype`;
   - `io.oz.album.peer.AlbumResp` (base `DocsResp`): field `profils` (Java's spelling); skip `forest`, `photos`, which can't be expressed;
   - `io.oz.album.peer.AlbumReq` (base `DocsReq`): `SynDocollects` is a `ServPort<AlbumReq>`, a `DocsReq` body will fail.
2. After login, request `A.getPrefs` with Doclientier's session via `commit<AlbumResp>()`.
3. Drop `weburl_of()`, and the web url update in `ping_synode()` and on saving (the "Link web url" check box in `user.slint`).

Server (semantic-jserv), whichever way is kept:

- Reply one format, `getLocalWebroot(https)`.
- `reverseIp()` is null before `merge_ip_json2db()` (`localIp` is `ignoreFrom`), so `pubConfg()` may reply `null:port`; `reportRversedIp()` has a fallback.
- `reversedWebPort()` defaults `port`, not `webport` / `webProxyPort`, when 0, so it may reply `ip:0`.
- `SynDocollects.profile()` Javadoc says webroot is looked up in `syn_node.jserv`; the code returns `org.webroot` as is.

Android:

- `PrefsWrapper.loadPrefs()` overwrites a saved `albumroot` with `url_landing` (the `if / else` looks inverted).

## Done when

Both clients get the album web url from the same server reply, and the desktop no longer parses `ip:port` from a ping.
